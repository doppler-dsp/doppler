- **`dp_dll_steps_max_out` and `Dll.steps_max_out` take the input length, and return the true bound.** `dp_dll_steps_max_out (state, x_len)` and `Dll.steps_max_out(n)` return `segments x min(n, floor(2 n / P) + 1)` partials, `P` the code period in samples; the old zero-argument form returned 0 and its header said prompts never outnumber input samples, which is false at `segments` above 1: a one-sample call that completes a carried period at `segments` 4 emits four partials, and `Dll.steps` sized its buffer at the call's length, so it kept one and dropped three without a word. `Dll.steps` now sizes from the bound (an `out=` buffer must hold it, or it raises) (`dp_dll_steps` still stops at `max_out`, memory-safe). Loop behaviour does not change. ([#3283](https://github.com/doppler-dsp/doppler/issues/3283), [#3282](https://github.com/doppler-dsp/doppler/issues/3282))
