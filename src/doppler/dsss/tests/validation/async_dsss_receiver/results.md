## 3. Review — findings, with verdicts

- **F1 · GAP** — `steps_max_out()` returns 0, which is not a bound: a call that completes a carried code period emits that whole period's symbols, so at more than one symbol per period an `out` sized to the call's `x_len` drops symbols silently. At the specification's operating point (0.9 symbols a period) it never binds. Tracked as #2469.

- **F2 · GAP** — `differential` is inert here: it reaches MpskReceiver's `bits()` demap, and this object returns soft symbols only (`_test_differential_does_not_change_the_symbols`). Remove it or add `bits()`: #2471.

- **F3 · CONFIRMED** — A first hand-off can land off the carrier and never pull in. With `reacquire` off (the binding's default, and the error-rate harness's), 0 of the 26 bursts of the 415.1 error-rate sweep never settled (section 2.6): the refine handed over outside the carrier loops' pull-in, code lock came up and symbol lock never did. `reacquire` recovers a missed hand-off by searching again. The hand-off accuracy is #2409; `reacquire` as the default is #3092.

- **F4 · GAP** — The pre-despread carrier loop's lock flag (`car.locked`) uses the Costas default rule, which is sized against noise only: its thresholds were never sized for a miss rate under signal. At 415.1-B-1, 2.8 GHz and 4 dB, the signal's own metric sits on the declare threshold and the flag toggles in the data with the loop on frequency, which breaks the owner's rule that a working link shows no lock toggle in the data. The receiver never calls `dp_costas_configure_lock()`. #3176 carries the measurement and the closed-form statistic its sizing needs.

- **F5 · C-ONLY** — The lock detector's hysteresis, the release clock's edges and the hand-over domain are certified symbol by symbol and sample by sample in the C tests of section 1; the binding exposes only the flags, which section 2 reads.

- **F6 · FIXED** — Over the 26 of 26 bursts that settled, the error rate sits 0.72 to 1.13 dB from the BPSK bound (section 2.6), and the EVM over the same windows reads +0.65 to +1.02 dB over its ideal. Until #2495 the two disagreed: the Dll divided each code period's partials by that period's own signal-plus-noise magnitude, which compressed the in-phase error, so the EVM read near its ideal and the blind M2M4 2.4 to 2.8 dB above the applied Es/N0 while the error rate sat 0.9 dB from the bound. The Dll divides by a slowly tracked level now, its error circular, and the blind M2M4 reads -0.71 to -0.51 dB from the applied Es/N0, inside `dp_ber_report()`'s 3.0 dB (`DP_BER_M2M4_AGREE_DB`) at every point. Where the loss goes, stage by stage, is section 2.7: the cut into four partials a code period, the demodulator's loops and the front end's tracking.
