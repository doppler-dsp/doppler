- **Every `make` target runs on one declared interpreter, `.python-version` (3.12).** Unset, `uv` picked the newest Python on the box, and a fresh checkout on a machine with Python 3.15 failed to sync: no pillow 12.2.0 wheel exists for it, so pillow built from source and stopped on missing JPEG headers. `uv` now reads the file for every project command, and CI's non-matrix jobs read it too (their typed `python-version: '3.12'` and `'3.13'` literals are gone; the three `3.13` jobs were not deliberate). The Python matrix is unchanged: its floor, 3.9, is a matrix leg, not the default interpreter. `make lint` refuses a typed version in a workflow and a `UV_PYTHON` or `--python` set outside the one declared override, the smoke target's ([#3303](https://github.com/doppler-dsp/doppler/issues/3303)). A `make` no longer rebuilds the shared `.venv` under a running suite: the interpreter probe only asks, reading an existing `.venv` without syncing, and a nested `make` refuses a `.venv` on another Python in one line (`scripts/venv_guard.sh`). Before this, a `make` run with `UV_PYTHON` unset rebuilt a 3.14 venv as 3.12 and removed packages from the suite that was importing them.
