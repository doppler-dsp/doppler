## 1. The object — a front door, not an algorithm

`BurstAcquisition` composes one `acq_state_t`, built through `acq_create_burst()`, and forwards every call to it. There is no algorithm here: the physics — coherent depth selection, CFAR sizing, window tiling, the detection statistic — lives in `acq` exactly once and is certified in its own report.

| page | owns |
|---|---|
| [`acq`'s report](../acq/results.md) | everything this object does at runtime — the engine, its sizing, its statistics. **Not re-derived here.** |
| `native/inc/burst_acq/burst_acq_core.h` | the forwarding contract — the SSOT this report audits |

### 1.1 What a forwarder can get wrong

Re-measuring detection through the wrapper would certify the same engine twice and present the second run as independent evidence. What the wrapper *can* get wrong alone is delivery: an argument dropped, defaulted, or **transposed**.

Transposition is the characteristic defect of a thin wrapper because the type system does not help. `pfa` and `pd` are both doubles in (0,1); `reps` and `spc` are both `size_t`; `noise_mode` and `nthreads` are both `int`. Swap either pair and the object still constructs, still detects a strong signal, and is sized against the wrong numbers — which surfaces much later as a false-alarm rate nobody chose.

### 2.1 Every constructor argument reaches the engine

One parameter is varied at a time and the object's whole derived state is compared against the base configuration. Two things are required: each parameter must move **something** (it was not dropped or defaulted), and no two parameters may move the **same set** of quantities (a transposition would be invisible if they did).

### 2.2 Every method reaches the engine

| method | evidence it reached the engine | holds |
|---|---|---|
| configure_search_raw | the pinned grid is read back | True |
| push | a burst rolled by 17 reports code_phase 17 | True |
| reset | a half-frame residue is dropped; matches a fresh object | True |
| get_state / set_state | a mid-stream blob resumes into a fresh instance | True |
| set_state (clobbered) | a bad envelope is rejected, not reinterpreted | True |

Each row is chosen so the engine must have *acted*, not merely been called: a code phase that matches the roll, a residue that was really dropped, a stream that really resumes. `push` returning a hit at the right phase is the strongest of them — it exercises the ring, the correlator and the CFAR gate in one call.

The serialized bytes **are** the shared engine's state; there is no wrapper format layered on top, which is why a blob taken here restores the whole search and not a subset of it.

### 2.3 An under-powered configuration says so

The object declares a post-construction warning gated on its own `underpowered` field — the manifest-driven diagnostic that turns a silently-too-weak search into something a caller sees. Nothing tested that it fires, which is the usual fate of a diagnostic: it is easy to declare and invisible when it stops working.

| configuration | warns |
|---|---|
| reps=2, cn0_dbhz=10 (cannot meet pd) | True |
| reps=8, cn0_dbhz=70 (comfortable) | False |

Both directions are checked. A warning that always fires is as useless as one that never does, and only the pair distinguishes them.

### 2.4 The derived identities, across three geometries

Each of these is a documented relationship between a constructor argument and a published field, so each is a second, independent check that the argument landed in the right slot. §2.1 proves the arguments are distinguishable; these prove where they went.

| geometry | sf | fs | code_bins | span (Hz) | bins/reps |
|---|---|---|---|---|---|
| reps=8, spc=4, 1 Mcps | 31 | 4M | 124 | 16129 | 8/8 |
| reps=16, spc=2, 3 Mcps | 31 | 6M | 62 | 48387 | 16/16 |
| reps=4, spc=8, 2.5 Mcps | 31 | 20M | 248 | 40323 | 4/4 |

`sf` is the code length, `fs` is `chip_rate * spc`, `code_bins` is `sf * spc`, the native span is `chip_rate/(2*sf)`, the resolution is `chip_rate/(sf * doppler_bins)`, and the coherent depth never exceeds `reps`. Six identities over three geometries: a `spc` that reached the `reps` slot, or a `chip_rate` that never arrived, breaks several of them at once.

## 3. Review — findings

- **F1 · BY DESIGN** — **This report does not measure detection performance, and that is the point.** `burst_acq_core.c` forwards every call into `acq_core.c`; re-running the detection statistics through the wrapper would certify the same engine a second time and present the result as independent evidence. The physics is certified in [`acq`'s report](../acq/results.md), which measures through this very front door. What is certified here is delivery — that every argument and every call arrives, and arrives in the right place.

- **F2 · FIXED** — **Argument delivery was pinned only by a single successful construction.** The C test builds one object and detects with it, which proves nothing about whether each argument reached its own destination: a wrapper that transposed two same-typed parameters would still construct and still detect a strong signal. §2.1 now varies each of the seven constructor arguments alone and requires (a) that each moves something, and (b) that no two move the same set — both hold. `pfa` and `pd` are the pair that matters: both doubles in (0,1), and distinguishable because `pfa` moves the threshold while `pd` moves only the look count.

- **F3 · FIXED** — **The under-powered warning was declared and never tested.** It is a manifest-driven post-construction diagnostic gated on the engine's own `underpowered` field, and it is exactly the kind of thing that stops working invisibly — a diagnostic nobody exercises is indistinguishable from one that was removed. Now checked in both directions (§2.3): it fires on a configuration that cannot meet the requested `pd`, and stays silent on one that can. A warning that always fires is as useless as one that never does, and only the pair separates them.

- **F4 · C-ONLY** — The forwarding of `burst_acq_destroy(NULL)` and the rejection of a NULL or zero-length code are certified in `native/tests/test_burst_acq_core.c`: neither is reachable from Python, where the binding owns lifetime and the array conversion refuses a malformed code before the C is entered.
