## Executive summary

- **Status.** **CERTIFIED** — all 83 limits hold.
- **Findings.** 25 recorded, 3 still open: F14, F15, F16.

**What a caller most needs to know**

- **The transform path is the brute-force answer** to 1.1e-07 across shapes and both reference kinds, so the FFT machinery, the scaling and the conjugation convention are all measured against something that shares none of them (§2.1).
- **CorrDetector2D's noise estimate is the object.** It is the denominator of every decision, and three of its four modes were exercised by nothing before its certification -- a mode selecting the wrong statistic moves every `test_stat` in the library without changing a single peak position (§2.12, F7).
- **Time-stamp each hit from its own anchor.** One push spanning several epochs emits several detections, each with its own `samples_consumed` — reusing one message-level timestamp for all of them is the mistake the field exists to prevent, and it was pinned by nothing until now (§2.21, F12).
- **Size the push against `n_noncoh`, not against epochs.** The auto-sizer routinely picks a look count above 1, so one dump needs several frames and a short push returns nothing at all — which reads as a broken detector rather than an incomplete dwell (F14, #999).
- **Any repeated preamble works; give a long one its Doppler rate.** The code, Zadoff-Chu, chirp, QPSK and a shaped QPSK all meet `pd_predicted` at 0.3, 0.6 and the default 0.9. The margin is thinnest at 0.9, +0.03 for the code (§2.28, F20). Without `doppler_rate` a long preamble is sized at a depth the drift takes away, 0.91 promised and 0.84 delivered (§2.29, F21).
- **BurstAcquisition is certified for delivery, not physics.** Its detection envelope is part three's (§2.19 to §2.29), and each of its seven constructor arguments moves a distinct set of derived quantities, so a transposition such as `pfa` and `pd` swapped -- both doubles in (0,1) -- cannot hide (§2.30, F23).

### 1.4 Part three: Acquisition — one engine, two mode-fixed front doors

`acq` jointly estimates a code phase and a Doppler bin and declares a detection when a CFAR statistic crosses an automatically sized threshold. The two constructors are not a convenience: a coherent slow-time axis can only ever resolve within one native span, and for a data-modulated stream a multi-epoch coherent axis aliases the data's transitions across the whole Doppler axis — a structural mislock rather than a graceful loss. So burst and continuous are fixed at construction.

### 1.7 What a forwarder can get wrong

Re-measuring detection through the wrapper would certify the same engine twice and present the second run as independent evidence. What the wrapper *can* get wrong alone is delivery: an argument dropped, defaulted, or **transposed**.

Transposition is the characteristic defect of a thin wrapper because the type system does not help. `pfa` and `pd` are both doubles in (0,1); `reps` and `spc` are both `size_t`; `noise_mode` and `nthreads` are both `int`. Swap either pair and the object still constructs, still detects a strong signal, and is sized against the wrong numbers — which surfaces much later as a false-alarm rate nobody chose.

### 2.2 Integrate-and-dump emits on the dwell-th call, and sums

| dwell | call pattern (. = held, D = dump) | dumped last |
|---|---|---|
| 1 | D | yes |
| 2 | .D | yes |
| 3 | ..D | yes |
| 5 | ....D | yes |

The dump is the **coherent sum**, not the last frame: correlating `dwell` copies of one frame and correlating it once at `dwell=1` differ by exactly the integer factor.

Measured: `|dump(dwell=3) - 3·dump(dwell=1)|` is **2.97e-07** relative — a sum, not an average and not a replacement.

### 2.3 The single-row fast path is exact (its flag is C-ONLY)

A reference that is nonzero only in row 0 makes `ref_spec[u,v]` independent of `u`, so the row axis of the 2-D transform pair cancels identically and `ny` independent 1-D transforms compute the same surface. The object selects that path itself; **the `fast_path` flag has no binding**, so which path ran is asserted in `test_correlator_core.c` and only the RESULT is checkable here.

| shape | fast path vs brute force |
|---|---|
| 4x8 | 4.54e-08 |
| 5x7 | 1.12e-07 |
| 8x16 | 1.15e-07 |

Worst **1.15e-07**. Measured against the external truth rather than against the general path: two implementations agreeing is blind to any defect they share, and the whole claim is that these two compute the same thing.

### 2.4 A larger inverse resolves a FRACTIONAL peak

`nx_out > nx` zero-pads the cross-spectrum before the inverse, giving the band-limited interpolation of the same surface on a finer grid. The claim is sub-bin resolution, so it is measured at sub-bin offsets — at integer shifts the native grid already lands on the answer and interpolation proves nothing.

|---|---|---|---|---|

| 16 | 3.25 | 3.250 | 0.000 | 0.25 |
| 16 | 3.5 | 3.500 | 0.000 | 0.50 |
| 16 | 3.75 | 3.750 | 0.000 | 0.25 |
| 15 | 3 | 3.000 | 0.000 | 0.00 |
| 15 | 3.25 | 3.250 | 0.000 | 0.25 |

The interpolated peak lands within **0.000** of a bin at every offset, on both parities of `nx`, while the native grid is off by up to 0.50 — which is what a half-bin offset costs when the grid cannot represent it. Raw sweep: `data/interpolation.csv`.

### 2.5 The interpolation keeps a real correlation real

The zero-pad splits the even-`n` Nyquist bin, and that split is invisible to a peak-location test — deleting it moves no peak. The invariant that sees it needs no reference implementation: a real input against a real reference gives a real correlation, whose spectrum is conjugate-symmetric, and the band-limited interpolation of a real sequence is real. An unsplit Nyquist bin turns `cos(pi t)` into `exp(i pi t)` — identical on the sample grid and complex between.

Worst imaginary part over the interpolated grid: **5.46e-08**, against a real peak of 1.109. With the split removed the same measurement reads 6.3e-03 — five orders of magnitude, which is what makes this a gate rather than a tolerance.

### 2.7 reset, and the state triplet

`reset` is measured as the header states it — *equivalent to starting a fresh dwell cycle* — rather than by reading the counter back. A partial dwell goes into one object, it is reset, and then it and an untouched object run the same full cycle: the dumps must agree. Reading `count` on a freshly created object, which is what the C test did, passes against a `reset` with an empty body.

Bit-identical after reset: **True** — a stale accumulator would carry the discarded frame into the dump.

A mid-dwell blob resumes bit-exactly into a fresh instance (**True**), and a clobbered envelope is rejected (**True**) rather than reinterpreted.

**A closed gate still updates what the object saw.** With the threshold raised past anything the surface produces, nothing is emitted and `last_corr` still peaks at the new input's position (**True**) — which is what lets a caller raise the gate and keep a diagnostic.

A dwell of 3 emits on the third frame and no earlier: `[0, 0, 1]`.

After a reset mid-frame the object behaves like a fresh one (**True**) — the ring residue is dropped rather than prepended to the next frame.

A mid-dwell blob resumes into a fresh instance (**True**) and a clobbered envelope is rejected (**True**).

### 2.19 The two front doors choose different machinery

| configuration | doppler_bins | n_noncoh | doppler_res_hz |
|---|---|---|---|
| burst, strong signal | 1 | 1 | 32258.1 |
| burst, weak signal | 8 | 1 | 4032.3 |

**Burst spends its budget on coherent depth**: a strong signal needs 1 bin(s) where a weak one exhausts to 8. **Continuous never does** — even with no uncertainty prior at all it reports `doppler_bins = 1` and buys its margin from non-coherent looks instead. ### 2.20 The native span, and what tiling is for

### 2.22 The threshold is a function of the cell count

The per-cell false-alarm rate is the system rate divided across every searched cell, so a search that grows also raises the bar on each cell. That is the price of coverage, and it is why a tighter uncertainty prior makes a **more sensitive** detector rather than merely a faster one.

| uncertainty | doppler_bins | pfa per cell | threshold eta | underpowered |
|---|---|---|---|---|
| 0.25 x span | 8 | 1.614e-06 | 5.1647 | True |
| 0.5 x span | 8 | 8.965e-07 | 5.2773 | True |
| 1 x span | 7 | 5.763e-07 | 5.3603 | True |
| 2 x span | 21 | 1.921e-07 | 5.5615 | True |
| 4 x span | 35 | 1.153e-07 | 5.6526 | True |

The threshold rises from 5.165 to 5.653 across a 16x range of uncertainty. A caller who can bound the Doppler tighter is buying sensitivity, not just runtime. No engine here meets `pd` at 45 dB-Hz with eight repetitions (`underpowered`), so `doppler_bins` is the sizer's best-effort depth -- the one with the most burst Pd above that depth's own false-alarm floor -- and re-pricing a gate can reorder that ranking: the tiled rows moved from D = 1 to D = 7 inside each tile when the gate began counting the interpolated rows (doppler#2218).

**The engine says when it could not meet the request.** At `cn0_dbhz = 10` with two repetitions `underpowered` is True, and at 70 dB-Hz with eight it is False. The flag is the difference between a detector that is configured for the link and one that merely constructed.

### 2.23 The rate it delivers, against the rate it was asked for

Every claim above is about how the threshold is DERIVED. This one asks the only question a caller actually cares about: push pure noise, count hits, compare against the configured `pfa`. The CFAR statistic is scale-invariant, so one number characterises it.

| target pfa | realized | ratio | sigma | frames |
|---|---|---|---|---|
| 1e-03 | 8.67e-04 | 0.87x | -1.0 | 60000 |

The detector delivers **0.87x** the false-alarm rate it was configured for (-1.0 sigma over 60000 noise frames). This run is deliberately cheap enough for `make validate-check`, so read it as a ratchet check rather than as the estimate: at a 1e-3 target, 60000 frames give ~60 expected hits and a Poisson spread near +/-0.13 on the ratio. The gate is priced over every row of the Doppler-interpolated surface its maximum ranges over (F19, fixed by doppler#2218); priced over the native rows it delivered ~1.8x. The count treats each interpolated row as a fresh look, which it nearly is in the tail, so the bound is conservative by a few percent (doppler#1064 holds the measured refinement). Ratcheted at 1.4x below.

### 2.24 The Pd it delivers, against the Pd it predicts

The full-band search never looked at its outermost native bin at an even depth (1/D of the prior undetectable, a Pd CEILING no C/N0 lifts), and the model derated scalloping over a native bin while the peak search samples an interpolated one. Measured here the way the model is defined: one preamble frame per trial, Doppler uniform over +/-span, code phase uniform in quarter-sample steps, AWGN at the design C/N0.

|---|---|---|---|---|
| D=8, 50 dB-Hz, full span | 0.612 | 0.710 | 0.026 | 300 |


The model is conservative by +0.098. What remains is the H1 face of F19's mechanism: the detector takes the maximum over an interpolated surface, and the Marcum form credits the on-grid cell only. That is the right side to err on for sizing; on H0 the same maximum is priced since doppler#2218.

### 2.26 The CFAR reference is a choice, worth ~15 dB

`noise_mode` picks how the reference cells are aggregated, and it had zero mentions in `test_correlator_search.c` and zero in `test_acq.py` — only the default was ever exercised. It is the denominator of the gating statistic, so the choice moves the engine's whole sensitivity.

| noise_mode | hits | noise_est | test_stat |
|---|---|---|---|
| mean | 2 | 24.8636 | 39.34 |
| median | 2 | 17.8828 | 54.70 |
| min | 2 | 0.4682 | 2089.40 |
| max | 0 | — | no detection |

Dividing by the smallest reference cell is a far more optimistic detector than dividing by the largest, so `min` produces the biggest statistic and `max` the smallest — and at a given signal level `max` can legitimately suppress detection entirely. That is the point of offering the choice, and it is now asserted as an ordering rather than left to the default.

### 2.29 A Doppler rate caps the coherent depth

A Doppler rate moves the carrier during a block and smears it across slow-time rows, a loss the Pd model does not carry. The burst constructors take `doppler_rate` (doppler#1482) and cap the depth at `f_epoch/sqrt(2*rate)` -- the drift rule the continuous engine already applies to its block depth. Measured on 16 repetitions of Zadoff-Chu 127 at 1 MS/s (`f_epoch` = 7874 Hz) under a 1.5 MHz/s ramp, sized by the engine at a C/N0 where it alone wants a deep block, 3000 trials a row. The ramp-free row is the control.

|---|---|---|---|---|---|---|
| no ramp (control) | 10 | 0.915 | 0.954 | 0.004 | +0.039 | yes |

| ramp (rate given) | 4 | 0.418 | 0.451 | 0.009 | +0.033 | yes |


Not told the rate, the engine is sized at the depth the Pd target alone picks and promises a Pd the ramp takes away. ### 2.30 Every constructor argument reaches the engine

One parameter is varied at a time and the object's whole derived state is compared against the base configuration. Two things are required: each parameter must move **something** (it was not dropped or defaulted), and no two parameters may move the **same set** of quantities (a transposition would be invisible if they did).

| parameter varied | fields moved | which |
|---|---|---|
| reps 8 -> 16 | 4 | doppler_bins, eta, pfa_cell, reps |
| preamble held 4 -> 8 samples a chip | 3 | code_bins, doppler_bins, doppler_span_hz |
| fs 4 -> 8 MHz | 6 | doppler_bins, doppler_span_hz, eta, fs, pfa_cell, underpowered |
| cn0_dbhz 55 -> 60 | 4 | cn0_dbhz, doppler_bins, eta, pfa_cell |
| doppler_uncertainty 0 -> 60 kHz | 3 | doppler_bins, eta, pfa_cell |
| pfa 1e-3 -> 1e-6 | 4 | doppler_bins, eta, pfa_cell, underpowered |
| pd 0.9 -> 0.99 | 5 | doppler_bins, eta, pd, pfa_cell, underpowered |
| doppler_rate 0 -> 83 MHz/s | 5 | doppler_bins, doppler_rate, eta, pfa_cell, underpowered |

All 8 move something (**True**), and all 8 signatures are distinct (**True**) — so no pair of arguments could be swapped without the table changing. `pfa` and `pd` are the pair worth naming: both are doubles in (0,1), and they move different things — `pfa` moves the threshold and the per-cell rate, `pd` moves the coherent depth (a burst engine never buys non-coherent looks, doppler#1181) and, past the ceiling, `underpowered`. Raw sweep: `data/forwarding.csv`.

### 2.31 Every method reaches the engine

| method | evidence it reached the engine | holds |
|---|---|---|
| configure_search_raw | the pinned grid is read back | True |
| push | a burst rolled by 17 reports code_phase 17 | True |
| reset | a half-frame residue is dropped; matches a fresh object | True |
| get_state / set_state | a mid-stream blob resumes into a fresh instance | True |
| set_state (clobbered) | a bad envelope is rejected, not reinterpreted | True |

Each row is chosen so the engine must have *acted*, not merely been called: a code phase that matches the roll, a residue that was really dropped, a stream that really resumes. `push` returning a hit at the right phase is the strongest of them — it exercises the ring, the correlator and the CFAR gate in one call.

The serialized bytes **are** the shared engine's state; there is no wrapper format layered on top, which is why a blob taken here restores the whole search and not a subset of it.

### 2.32 An under-powered configuration says so

The object declares a post-construction warning gated on its own `underpowered` field — the manifest-driven diagnostic that turns a silently-too-weak search into something a caller sees. Nothing tested that it fires, which is the usual fate of a diagnostic: it is easy to declare and invisible when it stops working.

| configuration | warns |
|---|---|
| reps=2, cn0_dbhz=10 (cannot meet pd) | True |
| reps=8, cn0_dbhz=70 (comfortable) | False |

Both directions are checked. A warning that always fires is as useless as one that never does, and only the pair distinguishes them.

### 2.33 The derived identities, across three geometries

Each of these is a documented relationship between a constructor argument and a published field, so each is a second, independent check that the argument landed in the right slot. §2.30 proves the arguments are distinguishable; these prove where they went.

| geometry | fs | code_bins | span (Hz) | bins/reps |
|---|---|---|---|---|
| reps=8, 124 samples, 4 MS/s | 4M | 124 | 16129 | 6/8 |
| reps=16, 62 samples, 6 MS/s | 6M | 62 | 48387 | 15/16 |
| reps=4, 248 samples, 20 MS/s | 20M | 248 | 40323 | 4/4 |

`fs` is the rate given, `code_bins` is the preamble's length `n`, the native span is `fs/(2n)`, the resolution is `fs/(n * doppler_bins)`, and the coherent depth never exceeds `reps`. Five identities over three geometries: an `fs` that reached the `reps` slot, or a preamble length that never arrived, breaks several of them at once.

## 3. Review — findings

- **F1 · FIXED** — `dp_correlator_reset` was pinned **vacuously**, which is the shape `docs/dev/contributing/validation.md` warns about by name. The C test called it on a freshly created object and asserted `count == 0` — already true before the call — so a `reset()` with an empty body passed, and the header's other promise, that it zeroes the accumulator, was asserted by nothing. Now measured as the header states it (§2.7). Sabotage: dropping the `memset` takes the new check red and leaves the OLD one green, which is the vacuity demonstrated rather than argued.

- **F2 · FIXED** — The even-`n` Nyquist-bin split in `corr2d_zeropad_1d` — whose comment claims it matches `scipy.signal.resample` to machine precision — was covered by **nothing**. Proven by deleting it and watching the whole suite stay green, including the new sub-bin interpolation section, because the split changes the interpolated shape and barely moves its argmax. The invariant that sees it is realness (§2.5): 5.5e-08 with the split against 6.3e-03 without.

- **F3 · FIXED** — Sub-bin interpolation was pinned only at INTEGER shifts, where the native grid already lands on the answer. Now swept at quarter-bin offsets on both parities of `nx` (§2.4). Worth recording how the first attempt failed, because it reads exactly like an implementation defect: building the band-limited impulse with the phase ramp over `u = 0..nx-1` puts two equal peaks either side of a null at the true position. That sweep treats the upper bins as high POSITIVE frequencies rather than the negative ones they are, and no correlation surface has such a spectrum. With the frequencies signed the peak lands within a hundredth of a bin everywhere — the correlator was right and the stimulus was wrong.

- **F4 · BY DESIGN** — `nthreads` was once documented *accepted for API compatibility; ignored*, and this finding said so. Since #2666 it is real: the fast path's rows and the delay-Doppler columns fan out over a persistent pool, each worker on its own FFT plans, and a batch makes whole maps per worker (#2683). The forward guard this finding described is what now holds the design: the output is bit-identical at every thread count, checked in C at 1, 2 and 7 workers and here at 1 and 3 (§2.10). A threaded reduction that folded in completion order would break it, and the C test's sabotage of exactly that goes red.

- **F5 · FIXED** — `dp_correlator_create_2d` documented `dwell` as *"must be >= 1"* and enforced only the output-grid rule, so `dwell = 0` built an object that was not merely degenerate but **silent**: the dump test is `++count == dwell`, which zero never satisfies, so it accumulated every frame it was handed and emitted nothing until `count` wrapped at SIZE_MAX. A caller whose dwell came from a computed value that underflowed got silence and unbounded growth rather than a refusal. Found by §2.9's refusal check, which failed on the first run. Fixed at the primitive rather than in each caller: `dp_correlator_create_detector_2d` forwards its own `dwell` straight into this call, so both objects now refuse it and a second copy of the rule cannot drift. NULL is the whole error report by design — `docs/dev/contributing/error-convention.md` makes NULL the return for an invalid argument as well as an allocation failure, and the class's declared `create_error` (gh-482) renders it as a `ValueError`, which §2.9 asserts exactly. Sabotage-proven: removing the check takes the new C section red.

- **F6 · C-ONLY** — Three claims have no Python face and are certified in `native/tests/correlator/test_correlator_core.c` instead: `dp_correlator_set_ref` (no binding at all — including its contract that a fast-path object REJECTS a reference that is no longer single-row), the `fast_path` selection flag, and the native path's promise to allocate no interpolation scratch, which is only observable as NULL pointers. The last is now asserted with the padded path checked to allocate them, so it cannot pass on fields that are always NULL.

- **F7 · FIXED** — **Three of the four noise modes were exercised by nothing.** `DET_NOISE_MEDIAN`, `DET_NOISE_MIN` and `DET_NOISE_MAX` had zero mentions in the C test (then `test_detector2d_core.c`) and zero in `test_detector2d.py`; only the mean was ever selected. `noise_est` is the denominator of every decision this object makes, so a mode returning the wrong statistic would have moved every `test_stat` in the library without changing a single peak position. Now measured in both languages against the aggregate computed by definition, over a window where the four modes genuinely disagree. Sabotage-proven: forcing the estimator to `DET_NOISE_MEAN` regardless of the configured mode takes it red.

- **F8 · FIXED** — `set_ref` had no coverage in either language, and writing one found that the interesting branch is the refusal. An impulse reference is single-row, so the embedded `Corr2D` is on its fast path, and that path can only accept another single-row reference — a multi-row replacement is **refused**. That is the documented contract working rather than a defect, and it is now asserted on both branches, including that a refusal is non-destructive and leaves the object working on its previous reference.

- **F9 · FIXED** — The struct comment promises the last-dump fields are *"updated on every dump regardless of threshold"* — what lets a caller raise the gate and keep a diagnostic — and nothing asserted it. Getting a test that could actually fail took three attempts, and the two failures are the finding: asserting `_last_corr_valid == 1` after a gated push passes on the flag left set by the previous ungated one, and asserting `test_stat` alone passes because the stat (then `compute_stat_2d`, now `corr2d_detection_stat`) writes the peak position as a side effect. The check that discriminates pushes a peak at a DIFFERENT position under a closed gate and requires the reported position to follow it; only a sabotage that restores all five last-dump fields takes it red.

- **F10 · C-ONLY** — Two entry points have no Python face and are certified in `native/tests/correlator/test_correlator_detector_2d.c`: `dp_correlator_set_ref` (F8 above) and `dp_correlator_set_threshold` — the `threshold` property is read-only from Python, so a caller who wants to re-gate a running detector must rebuild it or drop to C. The last-dump scalars (`peak_row`, `peak_col`, `peak_mag`, `noise_est`, `test_stat`) are likewise C-only as scalars, though `last_corr` exposes the surface they are derived from, which is what §2.16 uses to reach F9's claim from Python.

- **F11 · FIXED** — `dwell = 0` was refused as `MemoryError`: jm's generated NULL check raised it for an invalid argument as well as an allocation failure (`docs/dev/contributing/error-convention.md`). Since the class declares `create_error = "ValueError"` (gh-482) it is a `ValueError` naming the parameters, and §2.18 now asserts exactly that, where it had accepted either. The refusal itself lives in `dp_correlator_create_2d`, which this flavor forwards to rather than carrying a second copy of the rule.

- **F12 · FIXED** — **`samples_consumed` was pinned by nothing, in either language.** It is documented as a per-HIT anchor precisely so a caller does not reuse one message-level timestamp across every detection in a push, and the failure it guards against is silent: stamping every hit with the same offset still detects in the right place, and only a caller correlating detections to wall-clock would ever see it. Now measured over a push spanning many epochs — every anchor distinct, strictly increasing, one dump's stride apart (§2.21). Sabotage-proven by stamping a constant, which takes it red.

- **F13 · FIXED** — **`noise_mode` had zero mentions in `test_correlator_search.c` and zero in `test_acq.py`** — only the default was ever exercised, on an engine whose constructor offers four. `noise_est` is the denominator of the gating statistic, so the choice moves the engine's sensitivity by more than an order of magnitude: on one burst the statistic spans ~15 dB across the four, and `max` can legitimately suppress detection entirely. Now asserted as an ordering — a property of the aggregation rather than of the draw. Sabotage-proven by discarding the configured mode at construction.

- **F14 · CONFIRMED** — **The auto-sizer's `n_noncoh` makes a short push silently produce nothing**, and it cost an hour here. At `cn0_dbhz = 55` with a 7-chip code the engine picks `n_noncoh = 4`, so one dump needs four frames — and a push sized in epochs returns zero hits in every noise mode. Read cold that says "the modes are broken" rather than "the dwell never completed". The engine exposes `n_noncoh` so a caller *can* compute the requirement, and `underpowered` flags an unmeetable request, but neither says how many samples a dump needs. The C test's own localization section already carries a comment warning about this, which is the clearest evidence it is a real trap. Left open as a usability gap rather than fixed here: [#999](https://github.com/doppler-dsp/doppler/issues/999).

- **F15 · GAP** — **No property reports the SEARCHED Doppler reach, and `doppler_span_hz` reads as though it does.** That field is the NATIVE half-range `chip_rate/(2*sf)` — documented correctly, and a constant of the geometry that does not move when window-tiling engages. At 4x the native span the engine really searches +/-80 kHz while `doppler_span_hz` still reports 16 kHz. The reach is `doppler_bins * doppler_res_hz / 2` and a caller must know that expression to answer the first question they have: is my uncertainty covered? Evidence that this is a trap rather than a nit — this report's own coverage limit was written against `doppler_span_hz`, with the header open, and failed at 2x span; the correct behaviour looked like a coverage bug for several minutes. The coverage itself is right and already swept in `test_correlator_search.c`. Filed as [#998](https://github.com/doppler-dsp/doppler/issues/998).

- **F16 · GAP** — **`Acquisition`, the continuous search, has one limit of its own in this report.** Continuous mode window-tiles with no prior (§2.19); everything else this part measures through the Python face runs the burst door. The continuous engine's runtime behaviour (the tiled search, the carrier coupling, threads, the peak list) is pinned in `test_correlator_search.c`, `test_acq_continuous.py` and the async DSSS receiver's reports, not here, so this report on its own overstates what it certifies for that front door. Left open: [#2923](https://github.com/doppler-dsp/doppler/issues/2923).

- **F17 · BY DESIGN** — `BurstAcquisition` and `Acquisition` are separate constructors rather than a mode flag, and the report measures the consequence (§2.19): with no uncertainty prior at all, continuous still reports `doppler_bins = 1` and buys margin from non-coherent looks. That reads like a missed optimisation and is the opposite — a coherent multi-epoch axis aliases a data-modulated stream's own transitions across the whole Doppler axis, which is a structural mislock. Closing the footgun at the constructor rather than pricing it as a tunable loss is the design decision, and `docs/design/acq-surface.md` §9 carries the argument.

- **F18 · BY DESIGN** — `cn0_dbhz_est` saturates once the true C/N0 exceeds what the code and geometry can resolve, because the CFAR reference cells then contain the code's own autocorrelation sidelobes rather than receiver noise. The header states this and §2.25 measures inside the linear region deliberately. Worth a caller's attention: the estimate is a floor on the true C/N0 at high signal levels, not a measurement of it.

- **F19 · FIXED** — **The detector delivered ~1.8x the false-alarm rate it was configured for; it now delivers the configured rate.** `acq_commit_thresholds()` sized `pfa_cell` from the NATIVE cell count `searched_bins * code_bins`, while the gate's maximum runs over the Doppler-INTERPOLATED surface. Zero-padding adds no new *information*, but a maximum over a finer sampling of the same band-limited process is stochastically larger: interpolation finds noise peaks that used to fall between bins, the scalloping-loss win of #1002 (~3.9 dB -> ~0.9 dB) applied to H0. The 0.89 'conservative native model' once quoted beside it was doppler#1183 (an even depth never searched its outermost bin), not cell correlation: with the band searched to its edge the native maximum is on target, and the delivered ratio was the interpolation factor alone (1.86-1.93x at 1e-3 on the burst engine, doppler#2218). doppler#2218 prices the gate over the cells the maximum ranges over (`acq_band_cells`: every searched row of the interpolated surface, times `code_bins`), at all three sites that price one. That is a never-exceed bound: an interpolated row is correlated with its native neighbours, so the count is conservative by what that correlation is worth (0.95-0.97x measured at 1e-3, 1e6 dwells a row), about 0.015 dB of sensitivity. The measured per-geometry `N_eff` that would recover it is doppler#1064's open refinement. §2.23 re-measures the delivered rate.

- **F20 · FIXED** — **A shaped template's `pd_predicted` was optimistic.** QPSK through a 5-tap low-pass delivered 0.02-0.03 less Pd than it predicted, at up to 3 sigma of 3000 trials. The cause was not the straddle but the noise reference: the gate divides by the mean magnitude of the surface, peak included, and a template's correlation energy OFF its peak lands in those cells. Shaping spreads that energy; a code's sidelobes do the same, far more (a 7-chip code at D = 1 delivered 0.23 against a predicted 0.92). The model now prices the finite, self-inflated reference (doppler#1501), and the shaped rows are conservative by 0.05-0.10 (§2.28). The ratchet this finding carried is now the same bound every template keeps (doppler#1483).

- **F21 · FIXED** — **The burst sizer ignored a Doppler rate.** It picked the coherent depth up to `reps` whatever the platform was doing, so a long preamble under acceleration was sized on a Pd the drift takes away: 0.92 promised, 0.65 delivered in §2.29. The burst constructors now take `doppler_rate` and cap the depth by the drift rule the continuous engine already used, from one helper (doppler#1482). Sabotage-proven in `test_correlator_search.c` and in the harness's spot check.

- **F22 · BY DESIGN** — **This part does not measure detection performance, and that is the point.** `burst_acq_core.c` forwards every call into `correlator_core.c`; re-running the detection statistics through the wrapper would certify the same engine a second time and present the result as independent evidence. The physics is certified in part three of this report (§2.19 to §2.29), which measures through this very front door. What is certified here is delivery — that every argument and every call arrives, and arrives in the right place.

- **F23 · FIXED** — **Argument delivery was pinned only by a single successful construction.** The C test builds one object and detects with it, which proves nothing about whether each argument reached its own destination: a wrapper that transposed two same-typed parameters would still construct and still detect a strong signal. §2.30 now varies each of the seven constructor arguments alone and requires (a) that each moves something, and (b) that no two move the same set — both hold. `pfa` and `pd` are the pair that matters: both doubles in (0,1), and distinguishable because `pfa` moves the threshold while `pd` moves only the look count.

- **F24 · FIXED** — **The under-powered warning was declared and never tested.** It is a manifest-driven post-construction diagnostic gated on the engine's own `underpowered` field, and it is exactly the kind of thing that stops working invisibly — a diagnostic nobody exercises is indistinguishable from one that was removed. Now checked in both directions (§2.32): it fires on a configuration that cannot meet the requested `pd`, and stays silent on one that can. A warning that always fires is as useless as one that never does, and only the pair separates them.

- **F25 · C-ONLY** — The forwarding of `dp_burst_acq_destroy(NULL)` and the rejection of a NULL or zero-length code are certified in `native/tests/burst_acq/test_burst_acq_core.c`: neither is reachable from Python, where the binding owns lifetime and the array conversion refuses a malformed code before the C is entered.
