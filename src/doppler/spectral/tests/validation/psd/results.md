Generated by `validate.py` in this folder. Every number is measured from the C implementation through its own binding; nothing is modelled. Re-run to regenerate.

## Executive summary

- **Status.** **CERTIFIED** — all 23 limits hold.
- **Findings.** 15 recorded, 4 still open: F12, F13, F14, F15.

**What a caller most needs to know**

- **A row is that frame's PSD.** The per-frame kernel equals accumulate-then-read bit for bit and reads a full-scale tone at 0 dBFS under every window and both references — the claim the Spectrogram stands on, certified in C (F4, §2.1).
- **The levels are absolute.** dB/Hz reads `var/fs` and band power reads `var` for every window and pad, within 5 sd of the estimator's own spread (§2.5).
- **The noise floor is a median.** It ignores tones on an eighth of the bins to within 0.05 dB, where a mean of dB would move 3 dB (§2.6).
- **Three of the old tests could not fail.** Reset, max >= min and the band partition passed whatever the code did; each now has an external truth (F2).
- **Two readouts can mislead, and are open.** A scalar readout's 0.0 is both 'no measurement' and a real 0 dB (#1957), and adjacent bands both count the bin they share, +3 dB on a DC tone (#1958). Check for a frame first, and do not sum a partition (F12, F13).
- **create refuses what would read wrong** (pad 0, an alpha outside (0, 1], a gainless window, an overflowing size), but Python sees a bare `MemoryError` until #1986 (F6-F11, F14).

# PSD — validation report

## 1. The object — an averaging periodogram and its measurements

`PSD` windows each length-`n` frame, zero-pads it to `nfft = next_pow_two(n * pad)`, transforms it, and folds `|X|^2` into a per-bin average (mean, EMA, max-hold or min-hold), stored DC-centred. It reads the average back as a spectrum and as the measurements a spectrum analyser makes. Its per-frame kernel, `dp_psd_frame_power` / `dp_psd_frame_db`, is what the Spectrogram composes.

## 3. Review — findings

- **F1 · FIXED** — **The kernel's claims were mostly unpinned.** `frame_db`'s 0 dBFS 'whatever the window' was asserted for the rectangular window only, `bits` and `full_scale != 1` had no C test at all, and the -200 dB floor, negative bins and padded layout, rect ENBW and `nfft` were absent. Now C T1-T5 and T18 (#1955). The sharpest illustration is a sabotage: making the dB reference use `n^2` instead of `cg^2` left the existing kernel-equality test GREEN, because both of its paths share the reference; rect cannot see it either, since `cg = n` there. Only T2, over the tapered windows, goes red.

- **F2 · FIXED** — **Three existing checks were vacuous.** Reset re-fed identical frames in mean mode, where Welford's count = 1 step re-seeds whatever reset did; `max >= min` per bin passes with two MEAN states; and the band partition compared `total_band_power` with the sum of the same per-band values. Each is replaced by an external truth in C (T9, T10, T12; #1956) and measured again in §2.4 and §2.5.

- **F3 · FIXED** — **The certification's own first tests had to be corrected, and the corrections are the evidence they measure something.** (i) T8's fold check fed real frames only; on a Hermitian frame +k and -k carry equal power, so a fold that doubled +k passed — sabotage S8 found it, and the complex-input fold (§2.7) closed it. (ii) The noise-floor level cannot tell a median from a mean of the dB values: at K = 256 they differ by ~0.003 dB. T14b puts tones on 1/8 of the bins, which moves a median by +0.045 dB and a mean by +3 dB (§2.6). (iii) The first SFDR layout carried a 5.1e-3 dB leakage bias, modelled in double to 1e-6 dB before the tones moved to N/2 apart (§2.6).

- **F4 · C-ONLY** — `dp_psd_frame_power`, `dp_psd_frame_db` and `dp_psd_frame_linear` (#1963), the per-frame kernel the Spectrogram composes, have no Python binding. They are certified in `native/tests/test_psd_core.c`: one frame equals accumulate-then-read bit for bit (4 windows x n {64, 100} x pad {1, 2}), the average is untouched (T1), 0 dBFS under every window and both references (T2), the floor (T3) and the layout (T4); `frame_linear` in its own block: 10·log10 of it is `frame_db` above the floor, and a full-scale bin tone reads 1.0 under every window, padded or not, against `full_scale` and `bits`. §2.1-§2.2 reach the same transform through `accumulate`.

- **F5 · FIXED** — **The header described `n` where the code uses `nfft`.** `psd_db` writes `nfft` values (128 at `n = 64, pad = 2`), `psd_dbhz_max_out` is `nfft`, and the bin-to-frequency map runs over `nfft`; the file comment named two windows of four, and `beta` was 'ignored' for two of the three other windows. Prose, which jm carried to both faces; corrected in the header (#1959, §2.10 (a)).

- **F6 · FIXED** — **`pad = 0` was silently 1**, though the header documents `pad (>= 1)`. Refused now, like `n < 2` (#1959, §2.10 (b)).

- **F7 · FIXED** — **An exp-mode `alpha` outside `(0, 1]` was accepted and read wrong:** 0 never leaves the first frame, a negative alpha extrapolates (1x, 16x, 1x frames read -10.25 at -0.5), and above 1 is pass-through. AccTrace owns the rule; its create refuses and PSD returns that NULL (#1959, §2.10 (c)). AccTrace's own runtime `alpha` setter is outside PSD's face, which has no setter, and its two follow-ups live there: a refused value is kept silently in Python until just-makeit#2182 (#1987), and the value is not yet in AccTrace's state blob (#2000).

- **F8 · FIXED** — **`occupied_bw` accepted any fraction, through a private copy of the search.** A fraction outside the open interval `(0, 1)` reads NaN, `dp_obw_from_power`'s rule, and PSD's copy is deleted: it hands the averager's own double trace to the primitive. Without the copy's `cg^2` division equal bins sum exactly, so an edge on a bin boundary reads the exact width; C tie pins go red under that division at -O0, -O2 and -O3 (#1959, §2.10 (c)).

- **F9 · FIXED** — **A window with no gain built an estimator that read NaN or the floor.** Hann at `n = 2` is `[0, 0]`; a Kaiser `beta` of NaN, or from about 2.3e5 up, makes every tap NaN; a NaN `fs` or `full_scale` passed `<= 0.0`; `bits` above 64 overflows the reference. Each is refused at create (#1959, §2.10 (f)). One caller reached the Hann case mid-stream, AsyncDsssReceiver's carrier estimator at `refine_n_fft` 1 or 2, so carrier_acq's block floor is now 3, the shortest whose Hann has gain.

- **F10 · FIXED** — **`band_power` returned an empty array where its four siblings return `None`.** It returns `None` before a frame, or without a complete lo/hi pair (#1959, §2.10 (g)).

- **F11 · FIXED** — **`dp_psd_create(1 << 62, ...)` crashed:** `n * pad` and the byte counts wrapped. Refused before any allocation now, not left to calloc, which ASan and TSan report as an error rather than a NULL (#1959, §2.10 (i)).

- **F12 · GAP** — **A scalar readout's 0.0 means both 'no measurement' and a real 0 dB.** A floor scaled to 0 dB reads `noise_floor() = -0.0686`, next to the empty state's `0.0`, and `snr` over a band outside the span returns 0.0, the same as 'no SNR' (§2.10 (d)). Which sentinel is an API decision: #1957.

- **F13 · GAP** — **Adjacent bands both count the bin they share**, so a partition overstates the whole: a DC tone read as `[-fs/2, 0]` plus `[0, fs/2]` sums +3.01 dB above the whole span under the rectangular window (§2.10 (e)). Which band owns a shared bin is an API decision: #1958.

- **F14 · GAP** — **Every refusal above reaches Python as a `MemoryError` with no reason.** jm can raise the reason a component means (`create_error`, gh-482), and neither PSD nor AccTrace declares it yet: #1986.

- **F15 · GAP** — **The stubs do not say these readers can return `None`.** A `none_on_empty` readout's `.pyi` signature omits `| None` until just-makeit#2183 ships: #2001.
