# BurstDemod — validation report

## 1. The object — feedforward, so there is no second chance

`BurstDemod` recovers a spread burst end to end with no tracking loops: estimate from the preamble, dechirp, despread, sync-align, slice, check the CRC. Its entire output surface is the payload bits plus five read-backs, and a caller branches on one of them.

## 2. Characterisation

Measured behaviour. No verdicts — those are §3.

### 2.1 `frame_valid` rejects a frame that arrives and fails

This is the claim the object exists to make. It was pinned at 1 on a clean burst, and at 0 on an **8-sample** input — but that second case returns before a CRC is ever computed, so it is the *no frame at all* path. A `frame_valid` that ignored the trailer entirely and reported 1 for anything it decoded would pass both.

The case that separates them is a frame that arrives intact, aligns on the sync, produces its payload bits, and whose CRC does not match — one payload bit transmitted flipped **after** the trailer was computed.

| payload bit flipped | bits returned | frame_valid | bits differ from truth |
|---|---|---|---|
| 0 | 64 | 0 | True |
| 17 | 64 | 0 | True |
| 63 | 64 | 0 | True |

All three are rejected, at both ends of the payload and in the middle — and all three still **return their bits** (**True**), which is what makes this the CRC path and not the too-short path. A clean burst decodes and validates (**True**), so the rejections are not simply a demodulator that never works.

### 2.2 `frame_offset` and `n_symbols`, away from zero

`frame_offset` is documented as the symbol offset of the sync word, and was only ever observed as 0 — which is exactly what a read-back hardwired to zero also reports. `n_symbols` had no mention in either language.

| filler symbols before sync | frame_offset | n_symbols | expected | frame_valid |
|---|---|---|---|---|
| 0 | 0 | 93 | 93 | True |
| 3 | 3 | 96 | 96 | True |
| 9 | 9 | 102 | 102 | True |

The offset equals the filler count exactly, and `n_symbols` counts the **whole despread data section** — filler, sync, payload and trailer — not the payload alone. That distinction is what a caller slicing the soft symbols needs, and it is only visible once the sync is not at zero.

### 2.3 `reset()` clears the verdict

Documented, and called by nothing in either language. The read-backs are this object's whole output surface, so a reset that left them standing would report the **previous** burst's verdict for a burst that has not been demodulated — the worst failure a per-burst object can have, and a completely silent one.

| read-back | after a burst | after reset() |
|---|---|---|
| frame_valid | 1 | 0 |
| n_symbols | 93 | 0 |
| est_freq_hz | 48000.00 | 0.00 |

The precondition matters as much as the assertion: all three are **non-zero before** the reset (**True**), or the check would pass against state that was already clear — the vacuous-reset shape this campaign keeps finding.

### 2.4 The estimate the whole burst rests on

With no loops, the feedforward estimate is the only thing standing between the burst and a failed decode. It is `ppe`'s, certified there; what matters here is that this object hands it the right segment and reports it in the right units.

| read-back | injected | reported | error (Hz) |
|---|---|---|---|
| est_freq_hz | 48000.0 | 48000.0 | 0.0 |
| est_rate_hz | 0.0 | 0 | — |
| est_snr_db | — | 70.9 | — |

The injected residual is `F0 * fs` = 48000 Hz and the object reports it to **0.0 Hz** — in Hz, not in cycles per sample, which is the conversion a caller would otherwise have to guess.

| input noise sigma | clean decodes |
|---|---|
| 0 | 5/5 |
| 0.2 | 5/5 |
| 0.4 | 5/5 |

Five draws per level. The point is not a sensitivity curve — that is a characterization — but that the object decodes **every** burst at a noise level it is comfortable with, so the CRC rejections in §2.1 are attributable to the corruption and not to a marginal link.

### 2.5 What it refuses

| burst samples | bits returned | frame_valid |
|---|---|---|
| 8 | 0 | 0 |
| 64 | 0 | 0 |
| 512 | 0 | 0 |

A burst too short to contain a preamble returns no bits and no verdict, at three lengths. `demod_max_out()` reports 64 — the payload length, which is the buffer a caller must provide.

## 3. Review — findings

- **F1 · FIXED** — **`frame_valid`'s negative case was the too-short path only.** It was asserted 1 on a clean burst and 0 on an 8-sample input — but the latter returns before a CRC is ever computed. A `frame_valid` that ignored the trailer and reported 1 for anything it decoded would have passed both assertions, on an object whose entire purpose is to tell a caller whether the payload can be trusted. Now measured on frames that arrive intact and fail their own CRC — a payload bit flipped after the trailer was computed, at both ends and the middle — with the bits still returned, which is what distinguishes the CRC path from the too-short one. Sabotage-proven by forcing `frame_valid = 1` whenever a frame decodes.

- **F2 · FIXED** — **`frame_offset` was only ever observed as 0** — its degenerate value, and exactly what a read-back hardwired to zero reports. Now measured against bursts carrying 0, 3 and 9 filler symbols before the sync, where it must equal the filler count. Sabotage-proven by hardwiring it. Worth noting how the first attempt at that sabotage failed: the obvious regex matched the **initialiser** rather than the assignment, so the patch replaced `= 0` with `= 0` and the suite stayed green — a no-op sabotage reads exactly like a test that cannot fail.

- **F3 · FIXED** — **`n_symbols` had no mention in either language**, and it does not mean what its neighbours might suggest: it counts the whole despread data section — filler, sync, payload and trailer — not the payload. That distinction is invisible until the sync is not at offset zero, which is why it needed the same stimulus as F2. Sabotage-proven by reporting `payload_len` instead.

- **F4 · FIXED** — **`reset()` was called by nothing in either language.** The read-backs are this object's whole output surface, so a reset that left them standing would report the previous burst's verdict for a burst that had not been demodulated — silently, and in the direction that matters (a stale `frame_valid = 1`). Now checked with the precondition asserted first, so it cannot pass against state that was already clear. Sabotage-proven by making `reset()` return immediately.

- **F5 · BY DESIGN** — There is no state triplet and no `serializable` flag, correctly: the object is per-burst and feedforward, so there is no mid-stream position to checkpoint — a burst either completes within one `demod()` call or is lost. That is the same reasoning as `ppe`'s, one level up, and it is why `reset()` (F4) carries the whole burden of separating one burst from the next.
